# Map: Distributed Software Factory

## Destination

Sebuah **spec siap implement** untuk distributed software factory: tempat seluruh alur pengembangan perangkat lunak dijalankan — dari menyusun product requirement, sampai implementasi, review, dan test — sebagai pipeline berbentuk DAG yang didistribusikan ke worker yang didaftarkan. Sebagian step digerakkan agent sendirian, sebagian lagi menuntut manusia ikut di dalamnya. Web UI dipakai untuk menyusun pipeline, menjalani step yang butuh manusia, memeriksa artefak tiap step, dan memonitor run.

Spec mencakup domain model + ubiquitous language, arsitektur komponen, kontrak API control-plane↔worker, protokol step interaktif, model artefak, skema DB, format definisi pipeline, model auth & credential, dan keputusan fork-vs-dependency terhadap sandcastle.

Selesai ketika tidak ada lagi yang perlu diputuskan sebelum implementasi dimulai. Kode produksi bukan bagian dari destination; prototype throwaway boleh dibuat untuk menjawab pertanyaan desain.

## Notes

**Domain**: orkestrasi terdistribusi untuk AI coding agent. Basisnya [sandcastle](https://github.com/mattpocock/sandcastle) — library TypeScript yang menjalankan coding agent (Claude Code, Codex, Cursor, OpenCode, Copilot) di sandbox Docker/Podman/Vercel, dengan branch strategy untuk menggabungkan hasil kerja agent kembali ke repo host.

**Keputusan yang sudah dikunci sebelum map ini dibuat** (hasil grilling pembukaan — ini premis, bukan ticket):

- **Pengguna**: tim internal satu organisasi. Butuh login per-user, isolasi credential antar user, dan worker milik org. Bukan SaaS multi-tenant.
- **Bentuk pipeline**: DAG dengan fan-out. Satu run bisa pecah ke beberapa worker sekaligus, lalu bergabung lagi di step join.
- **Transfer state antar step**: git remote jadi bus-nya. Tiap step commit + push ke branch bernama; step berikutnya fetch branch itu. **Dikoreksi oleh ticket 01**: ini bukan sesuatu yang sandcastle berikan — `branchStrategy` bekerja sepenuhnya lokal dan tidak pernah push ke remote. Transportnya harus kita bangun sebagai wrapper.
- **Koneksi worker**: outbound-only, worker menarik kerja (long-poll/SSE/WebSocket) dari control plane. Control plane tidak pernah menghubungi worker. Worker di belakang NAT harus bisa ikut.
- **Stack**: pnpm monorepo TypeScript — `control-plane` (Hono atau Fastify), `worker` (CLI yang meng-import sandcastle), `web` (React + Vite), `shared` (tipe + skema Zod dipakai ketiganya). Postgres.
- **Self-hosted**: seluruh sistem harus bisa dijalankan sendiri oleh org. Tidak boleh bergantung pada layanan cloud terkelola yang tidak punya jalur self-host. **Dipersempit oleh ticket 11**: yang wajib self-hostable adalah **factory-nya** — control plane, Runner, web, Postgres. Git host adalah sistem eksternal apa pun pilihannya, dan tim sudah di **GitHub** sebelum factory ini ada. `GitHost` tetap interface bertubuh sempit dengan satu implementasi, jadi Gitea bisa masuk nanti tanpa membongkar apa pun.
- **Mode eksekusi worker**: "docker" vs "host" bukan arsitektur baru — itu memetakan langsung ke provider sandcastle (Docker/Podman bind-mount vs `branchStrategy: head` yang menulis ke filesystem host). Ini konfigurasi worker. **Dipersempit oleh ticket 12**: docker memakai provider `docker()` bawaan apa adanya, tapi host **tidak** memakai `noSandbox()` — provider host ditulis sendiri dan didaftarkan `tag: "bind-mount"` dengan mount identitas, karena `tag: "none"` mematikan session capture secara senyap.
- **Agent-in-the-loop dan human-in-the-loop**: keduanya kelas satu. Sebuah step boleh berhenti menunggu manusia — agent bertanya lewat web UI, lalu diam sampai ada yang menjawab. Ini bukan kasus pinggiran: lease, heartbeat, dan arti kata "hidup" harus dirancang untuk step yang idle berjam-jam. Butuh jalur dua arah UI ↔ sandbox, bukan hanya log streaming satu arah. Kasus acuannya: menyusun product requirement lewat grilling session di dalam web.
- **Artefak bisa diperiksa**: setiap step menghasilkan artefak yang bisa dibuka dan dibaca di UI. PRD hasil grilling adalah artefak markdown dari sebuah step, bukan entitas produk tersendiri. **Dikonfirmasi dan diperkuat oleh ticket 16**: rumah durable PRD adalah file di repo, Artifact cuma salinan yang tertinggal untuk dibaca, dan tahapan SDLC kelas satu dinyatakan out of scope.
- **Editor pipeline visual adalah generator**: arahnya visual → code. Yang dihasilkan adalah definisi berbentuk kode, bukan baris database buram. **Dijawab oleh ticket 08**: kode itu tinggal di repo, dan editor menghasilkan PR.

- **Bangun sendiri, dengan sandcastle sebagai dependency** — dikunci oleh ticket 00 dan 01, keduanya berdasarkan pembacaan source. Tidak ada kandidat open source yang layak dijadikan basis. Daftar pola yang layak ditiru beserta lokasinya ada di jawaban ticket 00; laporan lengkapnya di `research/`. **Dituntaskan oleh ticket 12**: dependency dengan **versi di-pin eksak** (`@ai-hero/sandcastle` `0.12.0`, bukan `^`), fork ditolak, `pnpm patch` jadi katup untuk perubahan kecil. Seluruh pemakaiannya diisolasi di `packages/runner/src/agent-runtime/` sebagai satu-satunya importir.

**Pola yang sudah diputuskan untuk ditiru** (detail dan sitasi ada di jawaban ticket 00):

- *Protokol worker* dari owainlewis/factory — query leasing dengan partial unique index sebagai constraint terakhir, dua heartbeat berwindow beda, sweep sebelum listener dibuka, idempotency dua lapis, batas log 10MiB. Seluruh lapisannya ≈1.650 baris Go, jadi ini modul berukuran sedang, bukan proyek tersendiri.
- *Abstraksi runtime* dari Warren — `RuntimeProvider` contract dengan `RunHandle` opaque, `RuntimeCapabilities`, dan `finalize()`. Sama-sama TypeScript, layak diadopsi hampir verbatim.
- *Model eksekusi dan state* dari Fabro — event sourcing per run di blob store, checkpoint sebagai git commit, graph engine lewat trait, sandbox trait yang sempit, cancel propagation sampai SIGTERM.
- *Dari luar*: Temporal untuk durable execution dan signal; Windmill untuk suspend/approve yang bertahan lama dan git sync visual↔code.

**Skills tiap sesi**: `/grilling` dan `/domain-modeling` untuk ticket grilling; `/prototype` untuk ticket prototype; `/research` untuk ticket research.

**Bahasa visual**: **token Corpus** dari `~/Code/lexicon/frontend/packages/design-system/src/styles/globals.css` — primary teal, skala neutral Primer, `--radius: 0.875rem`, skala bayangan/tipografi Figma, light dan dark. Dikunci ticket 17. Prototype 13 memakai palet lama dan sengaja tidak diperbarui: keputusannya soal bentuk, bukan warna.

**Bahasa**: user berbahasa Indonesia. Jawab dalam Bahasa Indonesia, istilah teknis biarkan dalam bahasa Inggris.

**Output research**: tulis ke `docs/design/distributed-software-factory/research/<nama>.md` dan tautkan dari ticket-nya. Direktori ini belum git repo, jadi tidak ada branch `research/<name>`.

## Decisions so far

<!-- satu baris per ticket yang sudah resolved -->

- [Apakah sudah ada yang menjawab kebutuhan ini](https://github.com/adryanev/factory/issues/81) — **bangun sendiri, sambil meniru pola dari keempatnya.** Tidak ada kandidat yang layak dijadikan basis: Fabro tidak punya konsep worker di mesin lain sama sekali (worker = subprocess yang di-spawn server sendiri) dan nihil multi-tenant; owainlewis/factory loopback-only secara sengaja dengan DAG terhalang di level skema; Warren justru **mundur** — fanout dan state `paused` pernah ada lalu dihapus. Sapuan lebar tidak menemukan yang lebih baik. Ticket ini juga membawa pulang daftar tiruan konkret dengan lokasi source-nya. **Dipersempit oleh ticket 25**: satu butir dari daftar tiruan dicoret — partial unique index `one_active_attempt_per_execution` melindungi model baris-per-attempt milik owainlewis, sementara ticket 06 mengunci retry menimpa baris yang sama, jadi primary key kita sudah memberikannya.
- [Domain model dan ubiquitous language](https://github.com/adryanev/factory/issues/84) — glossary ada di [`CONTEXT.md`](../../CONTEXT.md). Yang mengalir di Graph adalah **Ref + data terstruktur**, sehingga fan-out boleh dinamis; cabang dibedakan oleh **Key** bermakna, bukan indeks. **Output** (mengalir, punya kontrak) dipisah tegas dari **Artifact** (tertinggal untuk dibaca). Run menyimpan salinan penuh definisi dan Graph-nya sendiri. Credential menempel ke **Principal** (User atau ServiceAccount), tidak pernah ke Run. **Project** adalah unit isolasi; Repository adalah anggotanya. **Run adalah aggregate untuk penjadwalan**, log dan heartbeat ditulis di luarnya; **Runner** aggregate terpisah. Mesin disebut **Runner**, bukan Worker.
- [Prior art: orkestrator DAG dengan worker pull-based](https://github.com/adryanev/factory/issues/83) — **jangan ambil Temporal**: event sourcing + replay memecahkan masalah lain (kode imperatif arbitrer), sementara Graph kita sudah data di Postgres. Tiru **Windmill** — *"the worker is freed while suspended"*: StepRun `awaiting-human` adalah baris DB tanpa lease, Runner dan Sandbox dilepas total, resume lewat penjadwalan biasa, biaya infra nol. Key bermakna terbukti benar (Airflow harus menambal `map_index` belakangan). Join cukup kueri DB. Kegagalan sebagian: enum kecil per-Join, dan **pisahkan tegas "hilir dijadwalkan" dari "Run sukses"** — satu flag untuk dua pertanyaan adalah akar kelas bug `continueOn` Argo. Cancel lewat poll heartbeat, SIGTERM ke seluruh process group (GHA cuma menyinyal top-level, dan itu cacat yang mereka akui). **Peringatan: git sebagai bus adalah wilayah tanpa cetak biru** — Argo mendukung git sebagai input artifact tapi eksplisit menolaknya sebagai output.
- [Pilihan auth yang bisa self-hosted](https://github.com/adryanev/factory/issues/105) — **Zitadel** untuk Principal (Organization→Project→Role→Grant hampir 1:1 dengan kosakata kita; ServiceAccount kelas satu; audit event-sourced gratis; satu binary Go + Postgres). **Runner sengaja di luar Zitadel** — tabel `runners` + join token sendiri, ±100–150 baris, pola GitHub Actions runner dan bootstrap token kubelet; ini menjaga invarian Runner ≠ Principal secara struktural. Gugur: SuperTokens (multi-tenancy dan M2M berbayar), Ory Kratos (org di lisensi enterprise), Lucia (deprecated), better-auth (audit log memanggil layanan hosted). Catatan: Zitadel AGPL-3.0; alternatif session custom di atas Postgres tetap hidup kalau audit bawaan tidak sepadan dengan satu servis tambahan.
- [Penyimpanan dan pengantaran secret di CI self-hosted](https://github.com/adryanev/factory/issues/99) — **kelas ancaman baru**: CVE-2025-66032, prompt injection lewat isi GitHub issue membujuk Claude Code membaca `/proc/self/environ`, mencuri OIDC token, dan mendorong kode jahat. Kelima sistem CI yang dipelajari hanya mengantisipasi "penyerang menulis pipeline.yml", bukan "agent dibujuk lewat konten yang ia baca". **Redaksi log bukan kontrol utama** — bahkan Buildkite yang meredaksi client-side punya bug produksi nyata, dan semua vendor menyatakan redaksi tidak dijamin; kontrol utamanya **default-deny egress dari Sandbox**. Tidak ada sistem yang melakukan scoping per Principal — kesenjangan kedua tanpa cetak biru setelah git-sebagai-bus. Token repo per StepRun meniru pola Gitea, jangan tiru GitHub App. Woodpecker dan Drone menyimpan secret plaintext secara default — jangan ditiru.
- [Permukaan API dan titik ekstensi sandcastle](https://github.com/adryanev/factory/issues/82) — layak dipakai sebagai **dependency, tanpa fork**; API sepenuhnya runtime-argument-driven, provider dekopel dari Docker, live log tail tersedia. Tapi ia **tidak pernah push ke git remote**, tidak mendukung resume sesi lintas mesin, tidak punya redaksi log, dan cost tracking-nya hanya token mentah untuk dua agent saja. Semua kesenjangan aditif.

- [Step human-in-the-loop: interaksi, suspend/resume, dan arti "hidup"](https://github.com/adryanev/factory/issues/102) — **agent mengakhiri run-nya tiap kali bertanya**; tidak ada tool yang memblokir di dalam sandbox. `awaiting-human` = baris DB tanpa lease, Sandbox ditutup, Runner bebas, tahan-restart gratis. **Turn dan attempt dua penomoran terpisah** — retry policy membaca `attempt` saja; branch `run/<run-id>/<key>/t<turn>-a<attempt>`. **Session diangkut lewat blob store** (`readHostSession()` → blob → `hostSessionFilePath()`), jadi Runner interchangeable dan boleh di-drain selagi percakapan menggantung — ini konsumen ketiga blob store setelah log dan Artifact. **Question satu-satunya titik commit**: push branch → unggah session → POST Question; invarian *Question ada ⇒ ref dan session pasti ada*, mati sebelum POST = attempt baru dari turn yang sama. Tiga `kind` tertutup (`text`/`choice`/`approval`), `edit-artifact` ditunda ke ticket 15. **Penolakan adalah data** — `onReject: fail|continue` sebagai sifat Step, bukan tersirat di `approved:false`. Question ditujukan ke **audiens** bukan individu, jawaban pertama menang lewat compare-and-set, penjawab selalu dicatat. **Tanpa kadaluarsa bawaan** — menggantung tidak menyandera apa pun; visibilitas menggantikan timer. Cancel saat menunggu = penulisan baris DB, pola SIGTERM ticket 02 tidak berlaku. Rewind ditunda tapi laten — bahannya sudah tersimpan gratis. **Dikoreksi oleh ticket 25**: template nama branch di sini tidak memuat Key, jadi 50 cabang fan-out dari satu Step menghasilkan nama branch identik yang saling menimpa di remote; Key masuk ke template, dan keamanannya sebagai ref git dijamin tipe berkendala di ticket 23.

- [Siklus hidup worker dan pencocokan pekerjaan](https://github.com/adryanev/factory/issues/86) — **satu kolam Runner milik org**, seluruh siklus hidupnya di atas dua endpoint HTTP polos: `/claim` long-poll ≤30s dan `/heartbeat` tiap 10s yang sekaligus **satu-satunya kanal perintah** (cancel, `desired_state`, `latest_release`) — control plane tetap stateless, WebSocket/SSE ditolak. Masuk kolam lewat **join token sekali pakai** yang ditukar jadi runner-id + secret di disk; identitas ada di file itu, bukan hostname/IP. Kapabilitas: **fakta diprobe tiap start** (exec mode, agent CLI, cpu/ram), **kebijakan ditulis operator** (`slots`, label), hash-nya ikut heartbeat. **Matching terbalik** — Runner datang membawa tag, control plane memilih StepRun; kebutuhan sebagian besar tersirat dari Step, dievaluasi sebagai `runner.tags @> requires` **di dalam kueri klaim ticket 02**, bukan penjadwal terpisah. Slot ditegakkan Runner (penuh → berhenti poll) dengan control plane sebagai pagar. **Lease hilang memakan jatah `attempt` yang sama** dengan kegagalan biasa — satu penghitung, `reason` yang dicatat terpisah; ini yang memberi perlindungan poison-pill. Drain dan revoke lewat satu kolom `desired_state`; **revoke adalah fencing, bukan pembunuhan**. Versi protokol integer terpisah dari rilis — Runner basi tetap terlihat tapi tidak pernah dapat kerja. Isolasi: **`exec:docker` bawaan**, host mode hanya lewat `runsOn: [exec:host]` yang disengaja; secret tidak pernah menyentuh disk Runner.

- [Model credential, secret, dan akses repo](https://github.com/adryanev/factory/issues/106) — **kunci Project menempel ke ServiceAccount**, bukan ke Project, jadi invarian "credential hanya di Principal" terjaga struktural; fallback User→ServiceAccount lewat `allowSharedAgentCredential` (default **mati**), biaya selalu ke Principal pemicu. Git host **GitHub** ⇒ **GitHub App installation token wajib** — rekomendasi ticket 04 dikoreksi, karena `GITHUB_TOKEN` tidak bisa diminta pihak ketiga dan sisanya gugur terhadap premis 07. Token **di-mint dua kali per giliran** (fetch + sebelum push; umur 1 jam, tidak bisa refresh), `repository_ids` sempit, `contents:write` saja, `DELETE` saat teardown. Ini muat **karena** ticket 14 melepas Sandbox tiap giliran — kebetulan beruntung, bukan desain. AES-256-GCM dengan **AAD = secret id + owner Principal id**; master key dari **file**, bukan env var, karena `/proc/self/environ` adalah vektor CVE-2025-66032. `.sandcastle/.env` **tidak pernah ditulis** — `run()` menerima env langsung. **Koreksi bingkai ticket 04**: default-deny egress hanya menahan tujuan *tak dikenal*; jalur eksfiltrasi CVE itu adalah push ke repo, yang kita izinkan — yang menahannya adalah `repository_ids` sempit + **branch protection wajib**, dan factory **hanya membuka PR, tidak pernah merge**. **Xcode menaikkan `exec:host` jadi jalur rutin**: VM macOS ephemeral (tart) ditolak sebagai redundan, penggantinya **agent jalan sebagai user OS terpisah** dari proses Runner — tanpa itu agent tinggal `cat runner.secret` dan naik jadi Runner. Premis 07 diubah: secret tidak pernah **menetap** di disk Runner. **Rotate ≠ revoke-as-compromised**: rotate tidak mengganggu Run berjalan, karena rotasi yang membunuh Run membuat orang berhenti merotasi. Lima hal yang sengaja tidak dilindungi ditulis eksplisit.
- [Model auth, tim, dan otorisasi](https://github.com/adryanev/factory/issues/88) — **login GitHub OAuth, dan ini membatalkan Zitadel**: nilai jualnya (federasi multi-IdP, role grant, audit bawaan) tidak terpakai dengan IdP tunggal, jadi sisanya tabel Postgres + ~150 baris, lolos AGPL-3.0 dan satu servis untuk di-backup — cabang yang memang sudah disediakan ticket 03. **Identitas GitHub hanya untuk otentikasi, tidak pernah otorisasi** (bug akar CVE-2025-66032 adalah kode yang mempercayai suffix `[bot]`, yang bisa didapat siapa saja gratis). **Satu akun break-glass lokal**, supaya pemadaman GitHub tidak mengunci kita keluar dari tombol cancel. Peran: **`admin` + `member` per Project, `owner` di level org** — `maintainer` ditolak karena memisahkan "menulis Pipeline" dari "menjalankan Pipeline" tidak berarti untuk tim internal. **`owner` org tidak otomatis dapat akses data Project** — ia harus menambahkan dirinya jadi anggota, dan itu teraudit; tidak ada superuser diam-diam. Izin `exec:host` adalah sifat Project yang diberikan `owner`. Otorisasi: **`Principal` argumen eksplisit** di tiap fungsi baca, ditegakkan tipe — context ambient ditolak karena mode kegagalannya diam. PAT sendiri (`sf_`, SHA-256, izin = izin pemiliknya, 90 hari) — **dibatalkan ticket 27**: sapuan seluruh map menemukan ia tidak punya satu pun konsumen, jadi PAT dihapus beserta jenis audit "Terbitkan PAT". `audit_log` **append-only ditegakkan di level DB**, nilai secret tidak pernah dicatat; sembilan jenis kejadian **jadi sepuluh** setelah ticket 27 (−PAT, +Cancel Run, +ubah `automation_enabled`).

- [Model artefak: apa yang dihasilkan sebuah step, dan bagaimana ia diperiksa](https://github.com/adryanev/factory/issues/90) — **Artifact tidak punya kontrak**, dan itu konsekuensi paling tajam dari pemisahan Output/Artifact di ticket 05: Runner melapor bebas, Step tidak mendeklarasikan daftar artefak, dan **upload yang gagal permanen tidak menggagalkan StepRun**. Jaminan "step ini harus menghasilkan PRD" ditulis di skema **Output**, bukan di daftar artefak. **Immutable, satu per StepRun, tanpa tabel versi** — suntingan manusia di giliran 7 adalah Artifact baru milik StepRun giliran 7, dan "riwayat PRD" adalah `WHERE key='prd'` diurutkan menurut turn; ini **membuka `edit-artifact` yang ditunda ticket 14 tanpa keputusan baru**. Stabilitas `key` lintas giliran hanya **konvensi**, dimitigasi normalisasi slug. **Diff dimaterialisasi jadi blob** saat StepRun berakhir (SHA jadi metadata) — ini yang membuat branch bebas dihapus dan melunasi lubang retensi ticket 14. **Engine: Garage**, karena `minio/minio` **diarsipkan 25 Apr 2026** dan penerusnya berlisensi EULA proprietary, bukan AGPL. Satu bucket `factory` + tiga prefix (`artifact/`, `log/`, `session/`), **semua artefak ke blob tanpa jalur inline Postgres** — ambang ukuran akan menggandakan jalur penghapusan. Presigned dua arah supaya control plane tak pernah memegang byte (premis 07); **upload dulu → catat metadata**, invarian *baris Artifact ada ⇒ blob pasti ada*; presigned GET 5 menit setelah cek izin. - [Skema DB](https://github.com/adryanev/factory/issues/95) — **tiga dari empat rekomendasi awal terbalik oleh fakta yang diperiksa saat sesi**, dan yang bertahan bertahan dalam bentuk lebih tajam. Karena vonis akhir **tidak bisa berubah lagi setelah Run berakhir**, `outcome` + `ended_at` nullable ditulis sekali bukan yang ticket 06 larang; dan `ended_at` ternyata predikat yang dituntut keempat sweep retensi ticket 15/18, jadi satu kolom melunasi dua sub-pertanyaan. **Drizzle** (ketiga konstruksi terpanas diverifikasi didukung; `sqlc-gen-typescript` gugur sebagai beta 0.1.3 sejak 2023 — kelas risiko yang persis ticket 12 tolak), dengan batas dua gaya ditarik di muka: hanya trigger, kueri klaim, dan sweep yang SQL tangan. **Id UUIDv7 base32 berprefiks, satu identitas** — kendala yang tak pernah tercatat adalah `run-id` disalin manusia ke `git checkout`; bisa dibangkitkan klien, dan itu yang membuat AAD ticket 10 (id harus ada **sebelum** enkripsi) gratis. **Koreksi ticket 14: nama branch bertabrakan pada fan-out** — templatenya tanpa Key, jadi 50 cabang menimpa satu sama lain di remote; Key masuk template dan dideklarasikan **tipe berkendala di ticket 23** supaya agent memperbaiki dirinya dalam giliran — normalisasi slug ditolak karena cek duplikat ticket 06 berjalan sebelum normalisasi, jadi `Frontend`/`frontend` lolos. `NULLS NOT DISTINCT` membuat sentinel tak perlu dan sekaligus menegakkan "Key duplikat menggagalkan Run" secara struktural. **Temuan: partial unique index owainlewis tidak diperlukan** — ia melindungi model beratribut baris-per-attempt, sementara ticket 06 mengunci retry menimpa baris yang sama, jadi primary key kita sudah memberikannya. `text`+CHECK menang atas pgEnum karena himpunan "tertutup" terbukti tumbuh (ticket 15 menambah `kind` keempat). Audit log append-only lewat **trigger, bukan REVOKE** — jaminan yang bergantung pada langkah operator adalah jaminan yang diam-diam tidak ada. Enam keputusan terakhir (biaya jadi tabel insert-only sehingga kolom anomali ticket 20 lenyap; `key_version` yang membuat rotasi bisa diinterupsi; pola `*_purged_at`; **dedup (Pipeline, SHA) harus partial index atau ia melarang rewind**; cache definisi butuh fill-on-miss agar "boleh dihapus" bukan kebohongan; snapshot definisi inline sebagai pengecualian bernalar terhadap ticket 15) diambil agent sendirian — ditandai belum diadu.

- [Packaging self-host](https://github.com/adryanev/factory/issues/110) — **dua dari sembilan sub-pertanyaan larut oleh fakta**: Garage v2.3.0 (`--single-node --default-bucket --default-access-key`) menghapus seluruh langkah init yang jadi isi sub-pertanyaan 1, dan **GitHub App manifest flow** menghapus langkah manual terberat sub-pertanyaan 8 — manifest kita yang menentukan izinnya, dan `POST /app-manifests/{code}/conversions` mengembalikan app id + PEM + webhook secret sekaligus, jadi kelas "izin salah dicentang" lenyap dan private key tak pernah lewat clipboard. - **Paket macOS ternotarisasi** — ticket 28 memilih skrip yang bisa dibaca di atas `.pkg`, dan tarball JS berprasyarat Node di atas biner tunggal; keduanya menghindari sertifikat Developer ID dan alur notarisasi Apple. Harganya: tiap mesin macOS baru menuntut Node terpasang dan seorang operator yang bersedia menjalankan skrip. Belum jadi ticket karena belum ada satu pun Runner macOS yang dipasang, jadi apakah prasyarat itu menyakitkan masih tebakan. Pemicunya: operator pertama yang menolak menjalankan skrip, atau mesin macOS kelima.
- **Identitas author commit yang dibuat agent** — ticket 10 mengunci push memakai installation token, dan ticket 27 menemukan pertanyaan yang tak pernah ditanyakan siapa pun: token menentukan *boleh push*, bukan *tertulis siapa*. Untuk PR editor pertanyaannya sudah dijawab (author = user penekan tombol), tapi untuk commit yang **agent** buat di dalam Sandbox belum — pilihannya `factory[bot]`, atau Principal pemicu Run, dan keduanya punya konsekuensi berbeda di CODEOWNERS, grafik kontribusi, dan pembacaan `git blame`. Belum jadi ticket karena belum jelas apakah tim ingin kerja agent muncul di grafik kontribusi manusia sama sekali — itu pertanyaan kebijakan tim, bukan pertanyaan desain, dan jawabannya menentukan bentuknya seluruhnya. Pemicunya: `git log` sungguhan pertama yang dibaca orang.
- **Push notification untuk mobile** — ticket 19 mengunci lencana sebagai kueri dan menolak email serta preferensi per-User, dengan alasan yang bersandar penuh pada *state yang terbaca, bukan kejadian yang dikirim*. Aplikasi mobile membalik premis itu: layar yang tertutup tidak bisa mem-poll, jadi push adalah kejadian yang dikirim, dan ia membawa serta token perangkat per-User — yaitu persis state basi yang ticket 19 rayakan ketiadaannya. Belum bisa dirumuskan tajam karena aplikasi mobilenya belum ada, dan tanpa itu setiap bentuk (FCM/APNs langsung, atau relay lewat webhook ticket 19 yang sudah ada) menuntut menebak seberapa sering orang benar-benar membuka Question dari ponsel. Pemicunya: aplikasi mobile pertama yang berjalan.
- **Long-poll `/claim` lewat `LISTEN/NOTIFY`** — ticket 26 mengunci implementasi tahan-nya sebagai poll kueri klaim tiap 1 detik per koneksi menggantung, dan menyatakan angkanya: 100 Runner = 100 kueri indexed per detik. `LISTEN/NOTIFY` menurunkannya jadi O(instance) dan bersifat **aditif murni** — satu koneksi LISTEN per instance, nol perubahan bentuk request. Belum jadi ticket karena aturan map menuntut ukuran sebelum optimisasi, dan pemicunya adalah angka kolam yang belum ada.

## Out of scope

- **SaaS multi-tenant dan billing** — pengguna sudah dipatok tim internal satu organisasi. Kalau nanti berubah jadi produk, itu destination baru, bukan lanjutan map ini.
- **Tahapan SDLC sebagai entitas kelas satu** — Requirement, Design, Ticket, Review dengan skema, layar, dan aturan transisi sendiri. Ditutup oleh [ticket 16](https://github.com/adryanev/factory/issues/103), yang menyerahkan manajemen pekerjaan ke GitHub dan menahan factory pada "apa yang sedang dan sudah dijalankan". Menariknya kembali berarti factory menjadi issue tracker kedua bagi tim yang sudah punya satu — itu destination baru, bukan lanjutan map ini, dan tidak ada keputusan model data di sini yang menyiapkan jalannya.
- **Pencarian log lintas Run** — arsip yang bisa dicari melintasi banyak Run, ditutup oleh [ticket 18](https://github.com/adryanev/factory/issues/91). Argo sendiri mengaku tidak memecahkannya (ticket 02), dan memecahkannya berarti indeks teks penuh atas ratusan gigabyte — komponen infra kelima setelah control plane, web, Postgres, dan Garage, dengan cerita backup dan upgrade-nya sendiri. Destination map ini adalah spec siap implement untuk **menjalankan** pipeline, dan spec itu lengkap tanpa mesin pencari. Log sudah jadi objek Garage dengan prefix yang bisa ditebak, jadi pengindeks eksternal bisa dipasang belakangan tanpa satu pun perubahan di sini — tapi itu destination baru, bukan lanjutan map ini.
- **Ambang tahan-sandbox untuk step interaktif** — menahan Sandbox beberapa menit untuk penjawab cepat, alih-alih melepasnya tiap giliran. Ditutup oleh [ticket 17](https://github.com/adryanev/factory/issues/104), yang menemukan bahwa pemicu yang dulu ditulis di kabut ini salah alamat: **tidak ada prototype yang bisa menghasilkan angkanya**, karena biaya setup per giliran hanya terukur di Runner sungguhan — dan Runner terpasang ada setelah destination map ini. Jalur utama ticket 14 (lepas Sandbox tiap giliran) sudah dikunci dan tidak bergantung pada ini, jadi spec tetap lengkap tanpanya; menahannya adalah optimasi aditif murni. Yang sudah dibawa pulang ticket 17 supaya tidak perlu dipikirkan dari nol: biayanya **dibayar di depan mata penjawab** — lima langkah berurutan dengan kotak jawaban tertutup — jadi ini pertanyaan tentang pengalaman penjawab cepat, bukan tentang efisiensi Runner. Pemicunya: Runner pertama yang terpasang, yang akan membawa angkanya sendiri.
- **Kubernetes, high availability, dan TLS di dalam compose** — ditutup oleh [ticket 28](https://github.com/adryanev/factory/issues/110). Compose satu mesin adalah satu-satunya bentuk deployment yang diuji; dua instance control plane berjalan **benar secara mekanis** karena lease ticket 24 sudah menanganinya, tapi tanpa load balancer, dokumentasi, atau uji — "tidak didukung", bukan "tidak mungkin", dan bedanya dinyatakan supaya tidak ada yang membangun di atasnya diam-diam. TLS diserahkan ke reverse proxy di depan karena memilikinya berarti memiliki cerita ACME, pembaruan sertifikat, dan DNS. Destination map ini adalah spec siap implement untuk satu tim internal; menariknya kembali berarti destination baru.
- **Aplikasi mobile Compose Multiplatform** — user menyatakan mobile menyusul, dan premis itu **sudah dibayar** di ticket 27: transport jadi REST + OpenAPI justru supaya klien Kotlin bisa dibangkitkan, dan sesi bearer dinyatakan sebagai satu cabang aditif di verifikasi. Tapi membangun aplikasinya adalah destination baru — ia membawa serta layar, navigasi, siklus hidup offline, dan push notification (yang duduk di kabut). Destination map ini adalah spec siap implement untuk factory beserta web UI-nya, dan spec itu lengkap tanpa aplikasi mobile.
- **Auto-provisioning worker di cloud** — worker didaftarkan manual oleh operator. Autoscaling dan provider Vercel sandbox tidak dispesifikasikan di sini. Bertentangan dengan constraint self-hosted, dan menambah seluruh cerita lifecycle mesin.
